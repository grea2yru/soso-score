# 아이패드 악보 뷰어 — 1단계 설계

- 날짜: 2026-09-02
- 상태: 승인됨
- 대상 기기: iPad Pro 13" (M5), iPadOS 최신
- 용도: 개인용 (App Store 배포 없음, 개발자 계정 직접 설치)

## 배경과 목표

피아노 연주 중 손을 쓰지 않고 악보 페이지를 넘길 수 있는 아이패드 앱.
전면 카메라로 얼굴을 추적해 **고개 돌리기** 또는 **윙크(한쪽 눈 깜빡이기)** 로
페이지를 넘긴다.

### 단계 계획

- **1단계 (이 설계)**: PDF 악보 뷰어 + 카메라 제스처 페이지 넘김
- **2단계 (별도 설계)**: MusicXML 렌더링 + 오디오 악보 따라가기(score following)

## 기술 스택

- Swift + SwiftUI (앱 전반)
- PDFKit (PDF 렌더링·페이지 전환)
- ARKit `ARFaceTrackingConfiguration` (얼굴 방향·눈 감김 blendShape 추적)
- UserDefaults (설정 저장)
- XCTest (제스처 판정 로직 유닛 테스트)

접근법 선정 이유: ARKit 얼굴 추적은 고개 좌우 각도와 왼눈/오른눈 감김 정도를
별도 계수로 초당 60회 제공하므로, Vision 프레임워크로 직접 신호 처리하는 것보다
코드가 적고 정확하다. 대상 기기가 M5 iPad 한 대이므로 구형 기기 호환(Vision)이나
크로스플랫폼은 고려하지 않는다.

## 구성 요소

### ① 악보 보관함 (ScoreLibrary)

- PDF 가져오기: Files 앱 문서 선택기, AirDrop/공유하기(share extension이 아닌
  `onOpenURL` 방식), 앱 내 Documents 폴더에 복사 저장
- 격자형 목록: 첫 페이지 썸네일 + 제목. 제목은 가져온 PDF의 파일명에서 생성되며, 이후
  카드의 ⋯ 메뉴(또는 길게 누르기)에서 변경 가능 (파일명을 함께 바꿈)
- 항목 관리: 삭제, 제목 변경, 즐겨찾기 토글
- 즐겨찾기: 카드에 별 배지, 툴바의 별 버튼으로 "즐겨찾기만 보기". 전체 목록에서도
  즐겨찾기가 먼저 정렬. 제목 변경 시 유지, 삭제 시 함께 제거. UserDefaults에 파일명 배열로 저장
- 검색: 상단 검색창에서 제목 부분 일치(대소문자 무시)
- 악보별 마지막 열람 페이지 기억 (UserDefaults 또는 사이드카 메타데이터)

### ② 악보 뷰어 (ScoreViewer)

- PDFKit으로 페이지를 렌더링하되 배치는 직접 제어 (`PDFView`의 twoUp 모드는 홀수 마지막
  페이지를 가운데에 놓아 요구사항과 맞지 않음)
- 가로 모드: 책처럼 두 페이지 펼침(spread). 항상 1–2, 3–4 … 짝으로 묶고, 페이지 수가
  홀수면 마지막 페이지는 **왼쪽**에 홀로 표시. 세로 모드: 한 페이지
- 기본 샘플 악보: 드뷔시 「달빛」(Mutopia Project, 퍼블릭 도메인)을 최초 실행 시 보관함에
  1회 설치. 사용자가 삭제하면 다시 설치하지 않음. 출처는 `Samples/LICENSE.md`
- 수동 넘김: 화면 좌/우 영역 탭, 스와이프 (제스처 인식 실패 시 안전장치)
- 페이지 넘김 시각 피드백: 화면 가장자리 짧은 플래시 + 현재 페이지 번호 표시
- 얼굴 추적 상태 인디케이터: 초록(추적 중) / 회색(얼굴 미검출)

### ③ 얼굴 제스처 엔진 (FaceGestureEngine)

ARKit 세션에서 얼굴 데이터를 받아 `nextPage` / `previousPage` 이벤트만 내보내는
상태 기계. **판정 로직은 ARKit 타입에 의존하지 않는 순수 함수로 분리**하여
유닛 테스트 가능하게 한다.

입력(프레임당): 고개 좌우 회전각(yaw), 왼눈 감김(0~1), 오른눈 감김(0~1), 타임스탬프

#### 고개 돌리기 판정

- 발동 조건: |yaw| ≥ 임계값(기본 20°)이 최소 유지 시간(기본 0.3초) 지속
- 방향: 오른쪽 = 다음 페이지, 왼쪽 = 이전 페이지 (설정으로 반전 가능)
- 오인식 방지:
  - 발동 후 고개가 정면 복귀(|yaw| < 5°)해야 재무장(re-arm)
  - 발동 후 쿨다운(기본 1.5초) 동안 추가 발동 금지
  - → 연주 중 건반을 쳐다보는 자연스러운 움직임으로 연쇄 넘김이 일어나지 않게 함

#### 윙크 판정

- 발동 조건: 한쪽 눈 감김 > 0.8 이고 반대쪽 눈 감김 < 0.3 인 비대칭 상태가
  0.2초 지속
- 방향: 오른눈 윙크 = 다음, 왼눈 윙크 = 이전 (설정으로 반전 가능)
- 양쪽 눈이 함께 감기는 자연스러운 깜빡임은 비대칭 조건에 걸리지 않아 무시됨
- 발동 후 양쪽 눈이 모두 열려야 재무장, 쿨다운 적용
- 주의: ARKit blendShape의 left/right는 사용자 기준이므로 거울 반전 혼동에 유의

### ④ 설정 (Settings)

- 제스처 방식: 고개 / 윙크 / 둘 다(기본) / 끄기
- 민감도: 고개 각도 임계값, 윙크 감김 임계값
- 방향 반전 토글
- 쿨다운 시간
- UserDefaults 저장, 기본값은 위 판정 기준의 괄호 안 수치

## 데이터 흐름

```
전면 카메라 → ARKit 세션 → 제스처 판정(순수 로직) → 페이지 이벤트 → PDF 뷰어
                                     ↑
                              설정값(임계값 등)
```

## 오류 처리

- 카메라 권한 거부: 안내 문구 표시, 수동 넘김 모드로 정상 동작
- 얼굴 미검출(어두움, 화각 이탈): 상태 인디케이터 회색, 앱은 정상 동작
- 앱 백그라운드 전환: ARKit 세션 일시정지, 복귀 시 재개
- 손상된 PDF: 가져오기 시점에 열기 검증, 실패 시 오류 안내

## 테스트 전략

- 제스처 상태 기계: 얼굴 데이터 시퀀스를 흉내 낸 유닛 테스트
  - 윙크 vs 자연 깜빡임 구분
  - 고개 유지 시간 미달 시 미발동
  - 쿨다운·재무장 동작
  - 방향 반전 설정 반영
- 뷰어/보관함: iOS 시뮬레이터 수동 확인
- 카메라 제스처: 시뮬레이터에 전면 카메라가 없으므로 **실기기 테스트 필수**
